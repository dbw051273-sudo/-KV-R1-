## 导语：从 DeepSeek-R1 与 o1 的“万字思考”说起

自打 OpenAI o1/o3、DeepSeek-R1 以及 Qwen3-Math 等长思维链（Chain-of-Thought, CoT）推理模型爆火以来，大模型领域的核心范式正从单纯的“预训练扩展（Pre-training Scaling）”急剧转向**“测试时计算扩展（Test-Time Compute Scaling）”**。

一句话总结现状：**模型学会在推导中自发反思、回溯、自我修正，单次回答生成的 Token 数量从过去的几百字飙升到数千乃至数万字。**

然而，搞推理部署和系统（MLSys）的同学都知道，这背后藏着一颗巨大的显存炸弹——**Key-Value (KV) Cache 的爆炸式增长**。
- 以 8K 上下文为例，全量 FP16 的 KV 缓存动辄吃掉数 GB 显存；
- 如果扩展到 32K 乃至 128K 的极限长推导，显存占用直接突破几十 GB，并发 Batch Size 瞬间被压到 1，显存带宽与推理吞吐雪崩。

自然而然，学术界与工业界的主流呼声是：**“做 KV 缓存压缩/逐出（KV Eviction）啊！SnapKV、H2O、TOVA、R-KV 还有 Salesforce 前不久提出的 Random-Attention，挑重要的保留，不重要的删掉不就行了？”**

但慢着——**这些在 RAG（针海寻针）或中短对话里表现优异的压缩策略，搬到长思维链的多步数学严密推导中，真的管用吗？**

带着这个疑问，我们在过去不到两天的时间里，用单卡显存榨干的极限节奏，在 **Qwen3-1.7B、Qwen3-4B**（带 QK-Norm）以及对照模型 **Qwen2.5-1.5B**（不带 QK-Norm）上完成了 **2,745+ 次真实 GPU 运行**（全原生 BF16，拒绝量化放水），涵盖长程多步合成推导（Suite A）、50 道高难度竞赛题（MATH-500 自由生成）、开启原生思考（`enable_thinking=True`）的万字实测以及统一口径 CUDA 延迟压测。

测出来的结果，让我们和身边做大模型系统的同事都大吃一惊。

## 一、核心结论剧透：那些被顶会“神化”的策略是怎么翻车的？

如果你不想看繁复的技术公式，这里是五句大白话核心结论：

1. **注意力不是好尺子（Attention Collapse）**：主流的 SnapKV、H2O、TOVA 在长思维链上遭遇致命的“局部推导偏置”。Query 只看眼前的代数式，早期公理常数几乎分不到注意力，所有注意力头还协同“误杀”，**早期里程碑常量召回率直接全线归零（0.0%）**！
2. **随机淘汰是数学死穴（Markov Attrition Curse）**：Salesforce 最近主推的“无记忆独立随机淘汰（Random-Attention）”，在长推导面临 25+ 轮连续流式逐出时，早期常量的存活概率满足几何级数衰减 $(1 - \Delta / K)^R \to 0$。**多头并集全部灭绝，召回率同样是冰冷的 0.0%**。
3. **QK-Norm 不是元凶（对照实验实锤）**：有人推测是 Qwen3 的 QK-Norm 超球面投影搞坏了注意力。我们把 QK-Norm 剥掉，换成无 QK-Norm 的 Qwen2.5-1.5B 跑对照，**SnapKV/H2O 依然是 100% 暴毙（0.0%）**。这说明注意力坍塌是自回归多步推导的普遍内生缺陷，而不是某个特定架构的锅。
4. **值向量离散度才是时空不变量（Value Invariance）**：以当前 Token 的值向量偏离均值的 L2 范数（$\|v_i - \bar{v}\|_2$）为指标（ValueDiff），由于它只取决于语义本身而与未来 Query 无关，不仅在 Budget=512 下实现 **100% 完美召回**，在真实深度思考模式下也成功让模型做出了高难题。
5. **戳破迷信：短推导根本不存在“压缩胜过全量”的正则化神话！** 以前有论文称 KV 压缩后准确率比未压缩的 Dense 还高，归功于“剪枝起到了正则化作用”。我们用 750 次 MATH-500 生成加严格的配对 McNemar 检验，**$p$ 值全在 0.5 以上，统计学上毫无显著差异**，高出的 2%~3% 纯属采样随机噪音。

## 二、机理解剖 1：为什么注意力池化在长思维链中会“协同误杀”？

我们先来看大家最熟悉的 **SnapKV** 与 **H2O**。

它们的核心逻辑非常直观：在解码时，观察当前 Query 对历史 Token 的注意力权重，哪些 Token 累积的注意力权重高，就保留哪些。这在阅读理解（RAG）中很管用——因为问题是固定的，检索目标（针）在长文本里总会被反复点乘命中。

但在**长思维链多步推导**中，情况完全变了：
* 假设在第 100 个 Token 处，推导给出了一个关键初始常数：`M1 = 13`；
* 接下来模型进入了长达 2,000 个 Token 的漫长代数变形与多项式拆解；
* 在第 1,500 步解码时，当前步骤的 Query 向量完全聚焦于紧邻前序的几个 Token（这就是所谓的 **Recency Bias / 局部推导偏置**），根本不需要去看两千字前定义的 `M1`；
* 结果是：在滑动窗口的注意力累积中，`M1` 的累积分数越来越低；
* 更要命的是，多头注意力的各头在面对同一步代数变形时表现出高度的**语义协同一致性**。这意味着：不是某个头看漏了，而是 **16 个注意力头一致认为“M1 不重要”，联手把它从所有头的 KV 缓存中彻底剔除了！**

在生成到第 2,100 步需要调用 `M1` 做最终汇总时，模型回头一查缓存，`M1` 早已灰飞烟灭。在实测日志中，模型绝望地输出：“*根据前文推导，M1 的值为 [未定义]，无法完成求和*”。

## 三、机理解剖 2：Salesforce 的“无记忆随机淘汰”究竟错在哪？

前段时间 Salesforce AI Research 发布了一篇引人瞩目的工作（Random Attention，arXiv:2609.xxxxx），提出“与其费劲计算注意力，不如每一轮在非局部窗口内做纯粹的均匀随机淘汰”。

在静态问答中，如果仅发生 1~2 轮淘汰，随机淘汰确实可能撞大运保留一部分信息。然而在真实的流式推理中，**解码是持续进行的**：
* 序列每增长 $\Delta = 64$ 个 tokens，就会触发一次淘汰；
* 一次 2,000+ tokens 的推理，会连续触发 $R = 25 \sim 30$ 轮淘汰！

从概率论的马尔可夫链角度来看：
假设当前候选池大小为 $K$，每轮保留概率为 $p \approx 1 - \Delta / K$。那么经历 $R$ 轮独立的无记忆流式淘汰后，早期关键常数的单头存活概率为：
$$P(\text{Survival}) = p^R = \left(1 - \frac{\Delta}{K}\right)^R$$
当 $K=256, \Delta=64$ 时，$p = 0.75$。只要经历 $R=20$ 轮：
$$0.75^{20} \approx 0.00317 \quad (0.3\%)$$
即便是跨越全模型 $H=16$ 个注意力头取并集，早期事实全军覆没的联合概率依然是 $1 - (1 - 0.00317)^{16} \approx 4.9\%$，在 $R \ge 25$ 时**并集存活率严格趋近于 0**。

实测数据毫不留情：在两代模型、不同预算、多个种子的 1,300 余次测试中，`random_pp` 对早期里程碑常量的留存率**无一例外全部为 0.0%**。

## 五、解法与破局：为什么值向量几何范数能“拯救记忆”？

既然点乘注意力靠不住，随机淘汰又是自杀，那到底什么信号才能抵抗万字推导的漫长衰减？

答案是：**Value 向量自身的几何离散度（Value Difference Invariance）**。

在 Transformer 中，Key 和 Query 负责建立路由（Route），而真正承载语义信息并注入残差流的是 **Value 向量**。
- 一个普通的转折词或代数过渡符号，其 Value 向量通常紧贴词向量分布的中心均值 $\bar{\mathbf{v}}$；
- 而像 `M1 = 13` 中定义的常数、公理、或决定性解题步骤中的实体，在经过深度前馈网络（MLP）特征提取后，其 Value 向量会在高维表示空间中呈现出极大的正交偏离：
  $$\Delta v_i = \|\mathbf{v}_i - \bar{\mathbf{v}}\|_2$$
- **最关键的性质**：这个几何偏离度**完全是由当前 Token 本身的语义特征决定的，与未来的任何 Query 解码步统统无关！**

这就赋予了它“时空不变性”——不管后续模型推导了 1,000 步还是 10,000 步，只要这个常数足够关键，它的几何离散度就始终稳坐前排，永远不会被滑动窗口冲刷掉。

在真实开启原生深度思考（`enable_thinking=True`）的 MATH-500 测试中，单题思考达到 1,200 tokens 并连续触发 14 轮流式淘汰：
* **SnapKV** 在第 6 题与第 7 题中，因窗口收敛将初始同余基底误逐出，推导中途语义漂移，解题准确率只有 10.0%；
* **ValueDiff** 凭借几何范数稳稳锁死初始公理，**在 1,200 字超长严密思考后完美给出正确解答，保持了与未压缩全量 Dense 相同的 20.0% 准确率（100% 保全率）！**

## 七、统计学打脸时刻：“KV 压缩超过全量”到底是不是幻觉？

在很多 KV 压缩论文中，作者往往会骄傲地宣布：“我们在某个测试集上比 Dense 还高出了 2%~3%，说明剪掉冗余 KV 起到了正则化效果！”

**这是真的吗？**

我们在非思考模式下对 MATH-500 运行了 750 次自由生成测试（每种方法 50 题 × 3 种子），并做了严格的配对 McNemar 检验与 Bootstrap 置信区间计算：
* `snapkv_pp`: 42.0%
* `vacor_kv`: 41.3%
* `random_pp`: 38.7%
* `dense` (全量): 38.0%
* `valuediff_pp`: 38.0%

看着 `snapkv` 的 42.0% 好像确实比 `dense` 的 38.0% 高对吧？
然而，统计学检验结果显示：
* `vacor_kv` vs. `dense`: $p = 0.5000$
* `snapkv_pp` vs. `dense`: $p = 0.2500$
* `random_pp` vs. `dense`: $p = 1.0000$

**所有的 $p$ 值统统远大于 0.05！95% 置信区间高度重叠！**
所谓的 42.0% 相比 38.0%，在 50 题的测试集上其实仅仅意味着 **2 题的偶然答对波动**。连最无脑的随机淘汰 `random_pp` 都能测出 38.7%。

**结论**：在短推导下，KV 缓存压缩既没有造成智力损伤，也**绝对不存在所谓的神奇“正则化增强”**。压缩的唯一真理是**用微小的精度代价换取极致的显存与带宽释放**（在长上下文下实现 **102.4 倍显存压缩**），任何宣称压缩能大幅提升推理能力的宣传都经不起严谨统计学的推敲。
